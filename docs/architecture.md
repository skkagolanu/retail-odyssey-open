# Architecture

Browser → same-origin FastAPI → deterministic intent → validated catalogue → optional local model selection / image description → server-owned product cards and reply.

A server-issued 256-bit random HttpOnly/SameSite Strict cookie identifies each browser session. Only SHA-256 token hashes are stored in SQLite. History retains at most 20 messages (10 complete exchanges), adjustable to an even maximum of 100; prompts send at most eight historical messages. The default inactivity TTL is 24 hours and capacity is 1,000 sessions. Expired rows are pruned when sessions are resolved. This is bounded session storage, not account login or a deletion SLA for backups. A request-rate limit and global in-flight limit bound work; a reverse proxy must additionally rate-limit anonymous session creation for public deployments.

SQLite WAL transactions and per-session leases serialize requests across API workers sharing the same database. Clear resets all conversation fields and increments a revision. A reply from before that reset fails the revision/lease comparison and is discarded. Leases expire after 180 seconds, longer than the maximum request timeout. Async HTTP and thread-offloaded SQLite/Pillow calls avoid synchronous provider calls in the event loop.

Products are loaded from a strict catalogue schema. A real snapshot requires a timestamp and parsed HTTPS source hostname matching an allowed domain or its subdomain. Userinfo, non-443 ports, control characters and backslashes are rejected. URLs are never fetched by the application, and no remote image URL is accepted. Retailer allowlists constrain hostname ownership, not product availability or retailer redirects.

The model receives only candidate records and bounded history. Selected IDs must belong to the candidate set. Free-form model prose is validated for obvious commerce claims but is never displayed, even if it passes. The server renders catalogue facts and a deterministic response; image descriptions only influence retrieval. This avoids claiming that regex validation proves factual entailment. A catalogue snapshot can still be stale or incorrectly curated.

Provider results have response-size/time budgets; image uploads are limited to PNG/JPEG/WebP, four MB and 16 million pixels, then resized and re-encoded without source metadata. Request bodies are bounded even without Content-Length. Failed providers never fabricate image analysis or generated-image success. ComfyUI cleanup removes only this request's queued job and never globally interrupts another user's running job; a job already running may finish remotely after a timeout.

Metrics use bounded stage/route labels and exclude conversation text, cookies and images. HTTP timing spans final ASGI response completion; response-stage totals exclude session/database middleware and browser/network overhead. Session creation, clear, active sessions and actual returned product cards have separate definitions. Each API process has its own metric registry; scrape each worker separately or run a single worker. `/metrics` is operational data, not revenue, adoption or checkout conversion evidence.

## Agent orchestration and context management

Five separately implemented agents retain the original project's core orchestration design. IntentAgent plans which stages to invoke. VisionAgent returns a validated wardrobe description; RecommendationAgent consumes that description plus preferences/history and catalogue candidates; ConversationAgent consumes the selected records and same bounded context to generate a constrained styling plan. ImageGenAgent receives selected product records for optional ComfyUI generation. Greetings/about/scope refusal invoke local conversation handling and do not pretend to use a model. The retrieval tool stage is distinct from the recommendation model stage.

Immutable `AgentContext` values carry handoffs; agents never own or mutate a global conversation. The orchestrator records the ordered actual invocations, handoff field names, modes and outcomes. Image input is not retained in context/history or logs. Every turn has a random correlation ID, not a user/session identifier. Output schemas and post-validation keep unknown IDs and invalid plans from propagating. A failed recommendation uses the same catalogue and skips a redundant model conversation call. A failed conversation retains valid selected cards with a local reply; failed image stages explicitly report unavailable.

`TokenBudget` is scoped through Python ContextVar to the current async turn. Local calls reserve128 output tokens each and384 per turn; cloud reasoning calls reserve512 each and1536 per turn. All model calls together can reserve10,000 input proxy units. Local model context is4096; cloud calls enforce a4096-unit input/context estimate rather than changing the remote model context window. Input accounting conservatively counts UTF-8 serialized text/schema bytes, protocol overhead and an image reserve of2048. This is not an exact model tokenizer, and image token estimates remain model-dependent. Oldest complete history pairs are removed first, preserving system/current question. Requests that cannot fit or exhaust the shared allowance are refused before provider dispatch and use an explicit fallback. Actual provider-reported input/output counts are recorded separately; reservations are never described as consumed tokens. There are no hidden retries or provider switches.

Public generated styling is an enum-constrained plan (`advice`, `follow_up`) rather than unrestricted product prose. The server renders general styling advice from those validated codes alongside catalogue facts. This is a deliberate factuality boundary, not a claim that model factual support can be proven with regular expressions. Source records and vision observations can still be wrong; human evaluation remains separate.

## Profiling, logs and metric visualization

Each agent records elapsed wall time, actual invocation mode and status; HTTP completion and overall processing are separate boundaries. Correlated structured JSON log records exclude prompts, replies, image bytes, preference values and cookies. A bounded200-event process-local ring assists tests; durable log retention is the deployment operator's responsibility. Model token metrics distinguish reserved output limits from provider-reported input/output. Metrics and logs do not establish business usage, sales or individual users.

The frontend visualizes this turn's ordered agent invocations, handoff keys, latency meters and shared budget. The optional `compose.monitoring.yml` provisions Prometheus and a read-only Grafana dashboard for invocation rates, mean stage latency, HTTP p95, token use, provider failures, active sessions, clears and returned cards. Both ports bind loopback; no default administrator account/password is created. It is local operational tooling, not a public unauthenticated admin dashboard.

`python -m scripts.profile_pipeline` records cProfile cumulative timings for ten deterministic in-process catalogue turns including startup; it does not measure network/model latency or concurrent load. `scripts/benchmark.py` records real loopback HTTP timings and actual agent sequences. Separate real-model smoke reports identify actual completion/fallback. Mocked agent-contract tests verify sequence, cross-agent grounding, failure boundaries, budget isolation and schema enforcement, not model relevance.

The real cloud-agent adapter is described in [cloud setup](cloud.md). Its current contracts are tested without credentials; live hosted generation still requires private account setup and actual end-to-end verification. Free-plan confirmation is an operator declaration, not an independent billing audit.
